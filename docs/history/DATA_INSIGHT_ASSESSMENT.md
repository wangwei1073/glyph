# 数据洞察 / 变量关系 / 绘图指导：AI 必要性评估

> 背景：希望用 AI 做「解读数据集、查找变量关系、指导绘图」。
> 本文评估这三件事能否不用 AI 实现、哪些必须用 AI、以及推荐的技术路线。
> 结论：**约 80–90% 不需要 AI，而且统计与推荐应由本地确定性引擎完成。**
> 配套阅读：[AI_ASSIST.md](AI_ASSIST.md)（AI 的获益、成本与分阶段建议）。

## 一、结论

| 目标 | 不用 AI 能做到吗 | 建议 |
|---|---|---|
| 解读数据集 | **能**（列画像、质量检查、分布/异常/缺失） | 本地确定性引擎 |
| 查找变量关系 | **能且应该**（按类型选检验、效应量、多重校正） | 本地确定性引擎；统计量绝不让模型算 |
| 指导绘图 | **大部分能**（数据形态 → geom / 反模式规则） | 规则引擎 + 一键应用 |
| 听懂自由文本、理解列名语义、写图注 | **不能** | 可选 LLM 翻译层 |

核心原则：**R 算数、规则做推荐、AI 只做翻译。**
让模型计算 p 值/相关系数既不可靠，也不可复现；让规则处理自然语言则根本做不到。

## 二、能力拆解

### 2.1 解读数据集

**确定性可做（且比模型更准）：**

| 维度 | 指标 |
|---|---|
| 基本 | 行数、列数、列类型、重复行数 |
| 缺失 | 每列缺失数与缺失率、共缺失模式、整行缺失 |
| 分布 | min / max / 均值 / 中位数 / SD / IQR / 偏度、直方图分箱 |
| 类别 | 唯一值数、Top 值及占比、是否高基数（>30 类） |
| 异常 | 1.5×IQR 之外的样本数、极端值预览 |
| 结构 | 常量列、ID 样列（唯一率≈1 且名字含 id/uuid/key）、全空列 |
| 时间 | 日期范围、粒度、缺失时间点 |
| 组均衡 | 分组样本量、最小/最大组比 |

**AI 才补的：** 列名与单位的**语义**（`hwy`=高速油耗、`sbp`=收缩压）、数据集讲的是什么事、
领域惯例（临床/生态/经济）。内置数据集可以人工写描述（40 个，一次性成本）；上传数据只能靠
命名启发式 + 可选的人工填写。

### 2.2 查找变量关系

**确定性可做：**

| 变量组合 | 方法 | 输出 |
|---|---|---|
| 数值 × 数值 | Pearson + Spearman；差值大时提示非线性 | r、ρ、n、置信区间 |
| 类别 × 数值 | 组均值/中位数；ANOVA 或 Kruskal-Wallis | F/H、p、η²（效应量） |
| 类别 × 类别 | 列联表；卡方 / Fisher | χ²、p、Cramér's V |
| 日期 × 数值 | 对时间的线性趋势 + 分组趋势 | 斜率、p、R² |
| 多变量 | 相关矩阵 + 聚类（按 |r| 分层） | 关系分组 |

**工程约束（必须做对）：**
- 按变量类型选检验，不能一律 Pearson；
- 小样本（n<10 或组内 n<3）只给描述，不给 p；
- 多重比较用 BH 校正，报告**效应量排序**而非只看 p；
- 类别稀疏（组 <5）先合并或只提示；
- 缺失成对删除，并在结果里注明 n。

**AI 才补的：** 提出"可能值得看"的假设、把统计结果讲成人话、多步探索策略。

### 2.3 指导绘图

**确定性规则（数据形态 → 候选图）：**

| 数据形态 | 推荐 | 备注 |
|---|---|---|
| 1 连续 | 直方图 / 密度 | 偏态大 → 提示 log 轴 |
| 1 类别 | 条形图 / 点须图 | 类别 >8 → Top-N + 其他 |
| 1 类别 + 1 连续 | 箱线 / 小提琴 / 抖动散点 | 组内 n 小 → 点图优先 |
| 2 连续 | 散点；n>1000 → hex / 2D 密度 / alpha | 加平滑线提示关系 |
| 2 类别 | 堆叠/并列条、马赛克 | 关注比例时用 position=fill |
| 时间 + 连续 | 折线 / 面积 | 多点时提示抽稀 |
| 配对前后 | 斜率图 / 连线 | 需要 id 列 |
| 连续 + 分组 | 分面或颜色映射 | 类别 >7 时颜色难辨 → 分面 |

**反模式检测：**
- 过绘制：连续×连续 n>1000 且点重合 → 建议 alpha/jitter/hex；
- 类别过多：颜色或 x 轴 >8 类 → 建议 Top-N、分面或换图型；
- 离散值喂连续标度：数值列被当因子/字符 → 警告；
- 双轴误用：次轴量纲不一致 → 提示；
- 饼图/3D：给出"期刊通常不建议"的提示（可关闭）。

**一键应用：** 推荐卡片直接生成 spec（x/y/fill + geom + 默认主题/配色），可撤销。

## 三、AI 的不可替代部分

| 能力 | 为什么规则做不好 | 例子 |
|---|---|---|
| 自然语言 → 操作 | 意图歧义、多步规划 | "看看哪两个变量最能区分车型" → 扫描 + 排序 + 推荐 |
| 列名/单位语义 | 缩写、行业黑话 | `sbp`、`trt`、`visit`、`hba1c` |
| 图注/方法段落写作 | 需要组织语言 | "图 1 展示…，组间差异…" |
| 含糊需求澄清 | 规则无法反问 | "画个好看的图" |
| 解释"为什么这样建议" | 模板可给规则，但不够自然 | 需要结合数据上下文的解释 |

## 四、推荐架构

```
用户点击/输入
   ↓
确定性引擎（R，本地）
   ├─ profile(df)      → 列画像 JSON
   ├─ scan(df, cols)   → 关系 top-k JSON（带检验名、效应量、n）
   └─ recommend(df, x, y, ...) → 候选图 + 理由 + 可直接应用的 spec
   ↓
UI：洞察面板 / 推荐卡片 / 一键应用
   ↓（可选，默认关闭）
LLM 翻译层：只把自然语言映射成"调用哪个工具、哪些列"
           只发送列名/类型/聚合统计，绝不发送数据行
```

这样即使以后接 AI，也只是多一个入口；统计与推荐仍由本地引擎完成，可复现、可审计。

## 五、UI 方案（建议）

右侧新增「洞察」页签（或数据面板折叠区）：

1. **数据概览卡**：行×列、缺失最多列、常量列、ID 列、异常列 → 一句话警告；
2. **关系 Top 5**：按效应量排序，显示"变量对 + 检验 + 效应量 + 一句话解释"；
3. **推荐图卡**：缩略图 + 理由（"两个连续变量且样本 234，散点 + 平滑"）+ 「应用到画布」；
4. **导出**：把 profile / scan 结果写进可复现包的 `caption.md` / `profile.md`。

信息密度要克制：默认只展示 Top-5 与 2–3 个推荐，其余折叠。

## 六、实施计划与工作量

| 阶段 | 内容 | 估算 |
|---|---|---|
| 1 | 数据画像 + 洞察面板（只读，无推荐） | 3–5 天 |
| 2 | 关系扫描（按类型检验 + 效应量 + BH） | 5–7 天 |
| 3 | 推荐规则 + 反模式 + 一键应用 | 5–7 天 |
| 4 | 测试与金标准校准（mpg/iris/economics 等） | 2–3 天 |
| 合计 | 确定性 v1 | **约 2–3 周** |

## 七、验证与风险

**测试（可用内置数据集做金标准）：**
- `mpg`：`displ × hwy` 应给出强负相关（Spearman 约 −0.77）；`class × hwy` 应给出大 η²；
- `iris`：`Species` 与花瓣长度应强关联（η² 高）；
- 规则回归：同一 spec 的推荐必须稳定（快照测试）；
- 统计正确性：与 R 的 `cor.test` / `kruskal.test` / `chisq.test` 对照。

**风险：**
| 风险 | 缓解 |
|---|---|
| 统计误用（类型不匹配、小样本给 p） | 严格按类型派发、最小样本门槛、结果标注 n |
| 推荐平庸/套路化 | 给出"为什么"，并允许多个候选；按样本量与基数调整 |
| 大表扫描慢 | 分层抽样 + 上限（如 >5 万行先抽样），并在结果注明 |
| 列名语义错 | 命名启发式 + 用户可改列角色（连续/分类/ID） |
| 规则维护成本 | 规则表数据化（JSON），可测试、可增补 |

## 八、决策建议

1. **先做确定性 v1**（2–3 周）：覆盖你提出的三个目标里的绝大部分，零隐私风险、零 API 成本、可测试。
2. **AI 作为可选的翻译层**：只有当出现"用户想用一句话描述需求"或"上传数据的列名完全不可解"的真实需求时再上；
   即使上，也只让它调用本地工具、不接触原始数据。
3. **不要做的事**：让模型算统计量、让模型直接改 spec、把数据行发给云端。

## 附：与 AI_ASSIST.md 的关系

AI_ASSIST.md 回答"要不要引入 AI、成本多少"；本文回答"你想要的这三个能力，哪些其实不需要 AI"。
