# Tauri 桌面打包 · 成本评估

> 评估日期：2026-11-04 ｜ 结论：**技术可行，但收益有限，建议暂缓**
> 本文只做评估，未修改任何代码。体积数据为实测裁剪结果。

## 一、结论摘要

| 维度 | 评估 |
|---|---|
| 技术可行性 | ✅ 可行，无死路 |
| 工作量 | **约 5–8 人日**（不含 R 运行时合规与体积优化） |
| 安装包体积 | **≈ 75–85 MB**（R 运行时 69 MB 压缩 + 前端 6.5 MB + Tauri 壳 ~3 MB） |
| 真正的难点 | 不是 Tauri，是**把 R 运行时打包进安装包** |
| 建议 | 若目标只是「双击即用」，现有 `run_app.bat` + `dist` 已满足；Tauri 仅在需要**独立安装程序 / 自动更新 / 隐藏控制台窗口**时才值得 |

## 二、成本拆解

### 2.1 R 运行时捆绑 —— 占 70% 成本

实测裁剪结果：

```
裁剪后未压缩：139 MB
压缩后：      69 MB
（已剔除 doc/tests/Tcl/src/include 及所有包的 help/html/demo）
```

| 组件 | 体积 | 说明 |
|---|---|---|
| `bin/x64`（R.dll 38.6 MB + Rblas/Rlapack） | 43 MB | 不可裁剪，R 解释器本体 |
| `library/`（base+stats+grDevices+ggplot2 及递归依赖） | ~75 MB | 已去帮助文档 |
| `modules`（图形设备） | 21 MB | ragg / cairo 相关 |
| 其它（etc / share） | ~1 MB | |
| **合计** | **139 MB → 69 MB 压缩** | |

需要做的事：

- **可移植化**：R 默认写死 `R_HOME`，需相对路径自举（`Rprofile.site` 检测并重设），约 0.5 天
- **依赖裁剪脚本**：用 `tools::package_dependencies()` 递归解析并只保留必需包（当前为手工列举），约 1 天
- **安装包内解压 / 首次启动**：Tauri `bundle.resources` 只能原样携带文件；要么接受 139 MB 安装包，要么首次启动解压（需处理权限与进度提示），约 1 天

> ⚠️ **合规**：R 本体为 **GPL-2**。分发时需附带许可证与源码获取说明。仅捆绑未修改的 R 二进制并动态链接通常属于聚合（aggregation），风险可控，但须保留 LICENSE 声明。自有代码无需开源。

### 2.2 进程模型适配 —— 占 15%

现状是「R 起 httpuv 服务 → 浏览器访问 `127.0.0.1:4321`」，Tauri 中需变为「Tauri 起 R 子进程 → webview 指向本地服务」。

| 要改的点 | 位置 | 成本 |
|---|---|---|
| 启动时 spawn `Rscript run.R --port <空闲端口>` | 新增 Rust `main.rs` | 0.5 天 |
| 端口冲突处理（动态选端口并传给前端） | `run.R` 已参数化；前端需从注入变量读 base | 0.5 天 |
| 退出时结束 R 子进程（避免僵尸进程） | Rust `on_window_event` | 0.5 天 |
| 去掉 `browseURL` | `run.R:74` | 5 分钟 |
| webview 加载 `http://127.0.0.1:<port>` 而非内嵌资源 | Tauri `window.url` | 0.5 天 |

> 好消息：**前端几乎不用改**。`api.js` 全部使用相对路径 `/api/...`，只要 webview 的 origin 是该本地服务，同源策略与现有请求来源校验会继续生效。

### 2.3 文件系统与原生对话框 —— 占 10%

| 现状 | Tauri 中的问题 | 成本 |
|---|---|---|
| `downloadBlob()` 用 `<a download>` | WebView2 下载行为不可靠，无对话框 | 改 `dialog.save()` + `fs.writeFile`，0.5 天 |
| 上传用 `<input type=file>` + base64 | WebView2 通常可用（弹原生框），可保留 | 0（建议实测） |
| `pins.json` / `edits.json` 写在程序目录 | 安装到 `Program Files` 后无写权限 | 改到 `%APPDATA%`，0.5 天 |
| `plot_dir` 用 `tempdir()` | 可保留 | 0 |

### 2.4 构建与签名 —— 占 5%

- Tauri CLI 首次构建需下载并编译 Rust 依赖（约 10–15 分钟）
- 本机前置条件已全部满足：Rust 1.99、VS 2022、WebView2 156、Node 24
- MSI / NSIS 打包：**不签名**会触发 SmartScreen 警告；代码签名证书约 ¥1000–3000/年
- 成本：0.5 天（含首次构建调试）

## 三、必须提醒的三件事

### 3.1 体积从 6.5 MB 变成 ~80 MB

当前分发形态是「R 用户拿到源码 + dist（6.5 MB），双击 bat」。Tauri 版是「80 MB 安装包，装完占 150 MB+」。鉴于这是 ggplot2 工具，目标用户几乎必然已装 R，**这 70 MB 在很大程度上是冗余的**。

### 3.2 有更便宜的"桌面化"方案

| 方案 | 成本 | 效果 |
|---|---|---|
| A. `run_app.bat` 改 VBS 静默启动 | **10 分钟** | 无黑窗、自动开浏览器 |
| B. 单文件 `.exe` 包装（仍用系统浏览器） | 0.5 天 | 有 exe 图标 |
| C. **Tauri 包装** | 5–8 天 | 独立窗口、无浏览器、可自动更新 |

只有需要 C 档能力时才值得投入。

### 3.3 httpuv 单线程在桌面壳中会更明显

一次重渲染会阻塞所有请求。桌面壳中用户预期更高（"这是个 app，不该卡"）。若上 Tauri，建议顺带把渲染改为异步任务队列——但那是**另外 2–3 天**，不属于打包范畴。

## 四、推荐路径（若决定实施）

```
阶段 1（0.5 天）验证性原型
    tauri init，spawn R 子进程，webview 指向 localhost
    只验证「能打开、能出图、能退出」，不打包

阶段 2（1.5 天）可移植 R 运行时
    依赖递归裁剪脚本（tools/make_r_runtime.R）
    R_HOME 相对化自举
    首次启动解压到 %LOCALAPPDATA%

阶段 3（1 天）文件系统与对话框
    pins / edits 改 %APPDATA%
    导出走 dialog.save
    进程生命周期管理

阶段 4（1 天）打包与分发
    NSIS / MSI、图标、许可证文件、SmartScreen 说明

缓冲（1–2 天）WebView2 兼容性、DPI、杀软误报、真机验证
```

**总预算 5–8 人日**，其中 3 天以上花在 R 运行时上，与 Tauri 本身无关。

## 五、建议

**先别做 Tauri**。按性价比排序，先做这三件（都很便宜）：

1. **VBS 静默启动器**（10 分钟）—— 解决 90% 的「不像桌面应用」的观感问题
2. **pins / edits 改到 `%APPDATA%`**（0.5 天）—— 无论是否上 Tauri 都该改，装在只读目录会坏
3. **渲染异步化**（2–3 天）—— 真正影响体验的瓶颈

若之后确实需要安装包与自动更新，再走 Tauri；届时上述第 2、3 项已完成，Tauri 适配成本可从 5–8 天降到 **3–4 天**。

## 六、与统计功能的关系
