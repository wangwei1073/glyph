# AI 辅助绘图：获益与成本评估

> 评估对象：当前 master（P0 三项已完成）
> 问题：在一个**本地、离线、可复现**的科研绘图工具里引入 AI，值不值、怎么做、代价是什么。
> 本文只做分析，不改代码。

## 一、结论先说

**AI 值得做，但不该做成"核心功能"，而应做成"可选的辅助层"。** 理由：

1. 这个工具的核心资产是**确定性**：spec → 代码 → 渲染，同一份 spec 永远出同一张图。
   AI 只能生成 spec，不能替代这条管线；一旦让 AI 直接"画图"，可复现性就没了。
2. 目标用户是科研人员，数据常常是**未发表/受试者数据**。默认联网调用云模型，
   在很多机构是直接不可用的（IRB / 数据出境 / 保密协议）。所以必须默认关闭、显式授权。
3. 现有功能已经覆盖了很多"AI 会用来炫技"的场景（288 个标度可搜索、缩略图、导出检查、
   代码面板）。AI 真正稀缺的价值集中在四件事：**自然语言 → spec、报错解释、功能发现、图注写作**。
4. 成本不在 API 费用（很便宜），而在**工程复杂度、隐私合规、错误建议带来的信任损耗**。

**建议路线：先做"确定性智能"（规则式推荐 + lint），再考虑 BYOK 云模型，最后才评估本地模型。**

## 二、AI 能做什么：场景与性价比

| 场景 | 用户价值 | 实现难度 | 风险 | 建议 |
|---|---|---|---|---|
| 自然语言 → spec（"按 class 分组画 hwy 箱线图，用 Prism 风格"） | ★★★★★ | 中高（schema 约束 + 校验） | 生成错参数/幻觉 geom | **值得做**，但必须生成后可校验、可预览、可撤销 |
| 报错解释与修复建议（"Discrete value supplied to a continuous scale"） | ★★★★☆ | 低（错误文本 + spec 片段） | 解释错误 | **值得做**，最容易见效 |
| 图表类型推荐（按列类型/基数推荐 geom） | ★★★★☆ | 低（规则即可，不需要 LLM） | 推荐平庸 | **先做规则版**，AI 版后置 |
| 配色/主题建议（期刊风、色盲安全） | ★★★☆☆ | 低（已有 Prism/ggsci；规则匹配） | 审美主观 | 规则优先 |
| 导出合规解释与一键修复 | ★★★★☆ | 中（已有检查项，AI 只做解释） | 修复动作改坏图 | AI 只解释，修复用确定性代码 |
| 代码解释 / 改写（高级模式） | ★★★☆☆ | 低 | 改坏代码 | 可选，带 diff |
| 图注/方法段落写作 | ★★★★☆ | 低 | 编造统计描述 | 只基于已知信息生成，标注"需人工核对" |
| 数据清洗建议 | ★★★☆☆ | 中 | 误删/误改数据 | 低优先 |
| 多面板布局建议 | ★★☆☆☆ | 高 | 价值有限 | 不建议 |

**关键洞察**：上表里真正需要大模型的只有「自然语言 → spec」和「文本解释/写作」；
其余都可以用**规则 + 现有注册表**实现，零隐私风险、零延迟、零费用。

## 三、获益

### 3.1 用户侧

- **降低上手门槛**：288 个标度、167 个主题元素对新手是灾难；自然语言入口能把"找到那个选项"变成"说出你要什么"。
- **缩短排错时间**：R 报错对非程序员不友好，AI 解释 + 指向具体参数，能把"卡住 30 分钟"变成"30 秒"。
- **功能发现**：用户往往只用 5 个 geom；AI 可以提示"你的数据适合用 ridgeline / 小提琴"。
- **写作负担**：图注、方法段落是科研出图里最枯燥的部分，AI 草稿 + 人工核对能省时间。

### 3.2 产品侧

- **差异化**：同类工具里，"本地 + 可复现 + AI 辅助"是稀缺组合。
- **留存**：报错解释这类功能使用频率高、感知强，能显著提升"这工具懂我"的感受。
- **数据飞轮（谨慎）**：若将来做建议采纳率统计，可优化默认值与推荐规则——但必须默认不上报。

### 3.3 量化假设（用于判断值不值）

| 指标 | 现状（估） | 引入 AI 后（目标） |
|---|---|---|
| 新用户从打开到第一张合格图 | 15–30 分钟 | 5–10 分钟 |
| 常见渲染错误的自行解决率 | 低（依赖搜索/问人） | 60%+ |
| 功能发现（用过 ≥3 种 geom 的用户占比） | 低 | 提升 20–30% |
| 图注初稿耗时 | 10–20 分钟 | 1–2 分钟 + 核对 |

这些是假设，落地前应先用 5–8 个真实用户做基线测试。

## 四、成本

### 4.1 直接费用（比想象中低）

一次「自然语言 → spec」大约需要：系统提示 + 精简 schema（3–6k tokens）+ 用户请求（<100）
+ 输出 spec（0.5–1.5k）。按中端模型价格（$0.1–$1 / 百万输入，$0.3–$3 / 百万输出）估算：

| 使用强度 | 每月调用 | 估算费用 |
|---|---|---|
| 轻度（个人） | 100 次 | $0.2–$1 |
| 中度（课题组） | 1000 次 | $2–$10 |
| 重度 | 10000 次 | $20–$100 |

**真正的成本不是 token，是下面这些。**

### 4.2 延迟与体验

- 云模型首 token 0.5–2s，完整 spec 2–6s；本地 7B 模型 5–20s。
- 这个工具的核心卖点是"改一下 550ms 防抖自动出图"，AI 的秒级等待会打断节奏。
- 缓解：AI 只在**用户显式触发**时调用（"用一句话描述"按钮），不参与自动渲染链路。

### 4.3 隐私与合规（最大的隐性成本）

| 问题 | 影响 |
|---|---|
| 上传数据不能出境/出机构 | 云模型直接不可用；只能发 schema，不能发数据 |
| 列名本身可能含敏感信息（如 `patient_id`、`HIV_status`） | 即使只发 schema 也需脱敏/确认 |
| 机构 IRB / 数据保护法（GDPR、个人信息保护法） | 需要隐私声明、DPA、数据留存说明 |
| 离线/内网机器 | 云方案完全不可用，只能本地模型或规则 |

**结论**：云 AI 必须是 **BYOK（用户自带 Key）+ 默认关闭 + 明确告知发送内容 + 可预览将发送的 payload**。
这几点不做，就不要上线。

### 4.4 正确性成本

- LLM 会幻觉：不存在的 geom、拼错的参数、错误的 aes 组合。
- **本项目的独特优势**：AI 输出的是 spec，可以立刻用现有管线校验——schema 校验 → 代码生成 →
  试渲染（导出检查已经在做）。这能把"胡说八道"挡在落图之前。
- 即便如此，仍有"能跑但图不对"的情况（如把连续变量当离散），需要**预览 + 差异提示 + 一键撤销**。

### 4.5 工程成本（按人周）

| 工作 | 估算 |
|---|---|
| 规则式助手（图表推荐 / 参数 lint / 错误码映射） | 2–3 人周 |
| 云模型 BYOK（设置页、Key 管理、prompt 构建、流式、schema 约束、校验回环、diff UI） | 3–4 人周 |
| 上下文工程（meta 344KB 不能整包发送，需要检索/裁剪到 3–6k tokens） | 1–2 人周 |
| 评测集（50–100 条真实请求 + 期望 spec，自动跑通过率） | 1–2 人周 |
| 本地模型（Ollama 集成、模型管理、降级） | 2–3 人周 + 持续支持 |
| 文档 / 隐私说明 / 支持 | 1 人周 |

合计：只做"规则 + 云 BYOK"约 **8–12 人周**；加本地模型再 +3 人周，且长期维护负担明显。

### 4.6 维护成本

- 模型版本迭代、API 变更、价格变化、限流。
- Prompt 漂移：模型升级后输出格式变化，需要评测集兜底。
- 用户支持："为什么 AI 说的不对"——这类工单会持续存在。
- 安全：prompt injection（列名/数据里的指令）、Key 泄露。

### 4.7 信任与定位风险

- 科研工具最怕"黑箱"。AI 生成的图如果被审稿人质疑，用户需要能解释每一步——这也是为什么
  **必须保留 spec/代码可见**，AI 只能作为"帮你填 spec"的入口。
- 若 AI 建议质量不稳定，反而损伤"专业、可靠"的品牌。

## 五、三条技术路线对比

| | A. 规则式（无 LLM） | B. 云 LLM（BYOK） | C. 本地模型 |
|---|---|---|---|
| 隐私 | 最好（不出本机） | 取决于是否只发 schema | 好（不出本机） |
| 费用 | 0 | 低 | 硬件/电费 |
| 延迟 | <50ms | 2–6s | 5–20s |
| 能力上限 | 中（推荐/lint/错误映射） | 高（自然语言、写作） | 中低（7B 模型对 58 geom 的 schema 容易出错） |
| 离线可用 | 是 | 否 | 是 |
| 工程成本 | 低 | 中 | 中高 |
| 建议 | **先做** | **有条件做**（默认关、BYOK、可预览 payload） | 有明确离线需求再做 |

## 六、建议的分阶段方案

### Phase 1（2–3 人周）：确定性"智能"，不碰 LLM
1. **图表推荐**：根据列类型/基数/是否分组，在 geom 选择器顶部给 3 个建议（"你的数据适合：箱线图 / 小提琴 / 点图"）。
2. **参数 lint**：常见错误前置提示（连续变量映射到离散标度、箱线图缺 y、fill 映射到高基数列）。
3. **错误码映射**：把 R 报错翻译成"哪一层、哪个参数、怎么改"，附一键跳转到对应面板。
4. **图注模板**：基于 labs/数据源/统计方法生成结构化骨架（非 LLM）。

这一阶段零隐私风险、零费用，能吃掉 AI 场景表里一半的价值。

### Phase 2（3–4 人周）：BYOK 云模型，只做两件事
1. **自然语言 → spec**：输入一句话 → 生成 spec → **schema 校验 + 试渲染** → 展示"将要应用的变更"（diff）→ 用户确认才落地。
2. **报错解释/图注写作**：只发送错误文本、spec 摘要、列名（可勾选脱敏），不发送数据行。
配套：设置页（Key、模型、开关）、"本次将发送：…"预览、超时/失败降级、用量提示。

### Phase 3（按需）：本地模型
只有当出现明确的"内网/离线但想要 NL 入口"需求时再做，且默认只用于**解释/写作**，
不让它直接生成 spec（7B 模型的结构化输出错误率偏高，校验成本会吃掉收益）。

## 七、评估指标（上线前必须定）

| 指标 | 目标 |
|---|---|
| NL → spec 的 schema 合法率 | ≥95% |
| 生成 spec 的首次渲染成功率 | ≥85% |
| 建议被采纳后撤销的比例 | ≤10% |
| 报错解释"有帮助"评分 | ≥4/5 |
| 平均响应时间 | ≤4s（云） |
| 单用户月均费用 | <$2 |
| 隐私事件 | 0（硬指标） |

评测集建议：50 条真实需求（含中文口语、含糊描述、多图层），人工标注期望 spec；每次模型/prompt
变更自动跑，防止"升级后悄悄变差"。

## 八、风险与缓解

| 风险 | 缓解 |
|---|---|
| 生成错误 spec | schema 校验 + 试渲染 + diff 预览 + 一键撤销 |
| 数据/列名泄露 | 默认只发列名与类型；提供"脱敏预览"；明文告知发送内容；默认关闭 |
| 模型不可用/超时 | 降级到规则助手；AI 入口不阻塞主流程 |
| 费用失控 | BYOK + 用量提示 + 单次上限 |
| 幻觉功能名 | 只允许从 `/api/meta` 的枚举里选，禁止自由文本函数名 |
| 品牌受损 | AI 始终标注"建议/草稿"，不自动应用；保留代码可核查 |

## 九、决策建议

**做，但按上面的顺序做，且把 AI 定位为"入口/解释器"，不是"绘图引擎"。**

如果你的目标是"让工具更专业、更可信"，优先级应该是：

1. 期刊模板 + 合规面板（P1，确定性、差异化最大）
2. 物理尺寸预览 + 可复现包（P1）
3. 规则式智能（Phase 1）
4. BYOK 云 AI（Phase 2，视用户隐私政策而定）

**不建议现在做的事**：把 AI 做成默认开启、自动改图、或把数据发给云端。这三点任意一条都会破坏
"本地、可复现、科研可信"的产品定位，而收益远小于代价。

## 十、一句话总结

AI 对这个工具的最大价值不是"帮你画图"，而是**把 288 个选项翻译成人话、把报错翻译成下一步**；
最大成本也不是 API 费用，而是**隐私合规与错误建议的信任损耗**。所以：先规则、后 BYOK、
默认关闭、只生成 spec、永远可校验、随时可撤销。
